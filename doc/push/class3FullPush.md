# 类三 全量推: 整份覆盖 + 一个外生号

> 四类共用的部分在 [`../pushDesignAndReview.md`](../pushDesignAndReview.md);
> 协议信封在 [`protocol.md`](protocol.md); 选型在 [`index.md`](index.md)。

**一句话**: 这一桶整份推下去也不心疼(单份几 KB 以内, **按每帧算不是按一次算**),
所以不发明差量, 每次整份覆盖。典型是一堆标量状态、几百字节的小集合。

**id 是外生的**: 一个自增的 `Seq`, **数据本身说不出自己是第几版**, 只能另发一个号。

> **一条贯穿四类的判据: 只有类三需要一个外生的号, 也就只有它需要一个受保护的整数。**
> 任何时候你发现[类一](class1TextStream.md) / [类二](class2MsgStream.md)也想加锁,
> 那说明你在给它们发外生号 —— 回[选型](index.md)重新找它们的内生号。

**翻车形状是旧数据贴新号。** 号和数据一旦能分开被读到, 客户端就会拿一份旧数据当成最新的存下来,
而且**再也不会被纠正**(下一帧的号更大, 但那时旧数据已经落地了)。

## 1. 什么时候选它

选型三问的第二问答"是"。**但先过 2b 那一关**:

> 这一桶是不是"变得很勤 + 只关心最新值 + 差一两秒没人在乎"?
> (动画式进度、光标闪烁、会整屏重绘的终端输出、跑马灯计数器)
> 是的话**不能进类三** —— 类三的成本是 `变更次数 × 整份大小`, 这两个因子它都顶满了,
> 它会霸占每一帧的信封, 把真正高频的那一桶(类一)的带宽账吃掉。
> 出路见 [`index.md`](index.md) 的 2b: 首选退到[类四](class4Poke.md)。

**真实数字**: 一桶"看着才 1KB"的 TUI 黑框放在类三里, 每帧从 37 字节涨到 1183 字节。

## 2. 帧字段

    段: 整份字段(或字段级 diff: 缺席 = 没变)
    帧带: Seq

* **"没变"和"变成空"必须分得开** —— 用 `HasXxx` 布尔或 `*string` 指针。
  > 违反后果: "列表清空了"被当成"这次没带这个字段", 界面永远清不掉。
* 如果做字段级 diff: **这类帧必须带 `Seq` 才能剔重**, 因为它的应用不再幂等。
  > 这是四类里唯一一个"要带 `Seq`"的桶。判据是[协议篇](protocol.md)那句
  > **"只有重放会出错的帧才带 `Seq`"** —— 不是"带没带状态桶"。

## 3. 服务端: 那个号怎么发

这一桶的号住在房间快照里, 跟着快照一起原子换掉(手册 §4.1):

    写侧(worker): 读库 -> 组装一份全新的 state(Seq = 旧 Seq + 1) -> Store 指针 -> 广播
    读侧(进房):   Load 一次指针, 数据和 Seq 一起拿到

**这就是"只锁那一个整数"的实际写法**: 不是真加一把锁, 而是
**把号和数据放进同一个不可变快照, 用一次原子指针换掉**。
于是"读侧先读号还是先读数据"这条纪律**自动成立**, 只剩写侧要人守。

进房时(第三步):

    类三: 整份给, 标上快照里的 Seq

**`Seq` 从 0 起算**, 让零值不上线(编码器跳过零值, 别的桶的帧就不用白背一个恒为 0 的号)。

**`Seq` 只比大小, 不判连续。** 没有客户端可见变化的版本压根不发帧, 所以跳号是正常现象 ——
"漏帧没有"是传输层的事(同一条连接 FIFO + 装不下就断线), 不是 `Seq` 的事。

## 4. 客户端: 怎么应用

    Seq <= 我的  -> 扔
    Seq >  我的  -> **整份覆盖** 并更新我的 Seq

> 违反后果: 改成"字段级差量地应用", 幂等就没了, 于是要求号严格连续, 于是服务端又要一把锁。
> 这一类的全部宽容度("多收敛一次啥事没有")都来自"整份覆盖是幂等的"。

**两个"啥事没有", 记住它们就知道这一类为什么够用:**

* **锁住顺序是没有意义的, 只要锁住"变没变"。** 两个并发的读者谁的号大客户端就看谁,
  另一个被扔掉 —— 而被扔掉的那份数据一定是"某个真实存在过的版本", 不是拼出来的。
* **客户端多收敛一次, 什么事都没有。** 整份覆盖是幂等的, 多盖一遍等于没盖。

## 5. 这一类的降级路径

| 触发 | 动作 | 再来一次哪里不一样 | 有效? |
| --- | --- | --- | --- |
| 丢了一帧(**只可能发生在断线之后**) | **不用管** | 下一帧整份盖回来, 自愈 | ✅ |
| 这一桶变得太大 / 变得太勤 | **退回[类一](class1TextStream.md)或[类四](class4Poke.md)** | 重新走一遍[选型](index.md) | ✅ |

**注意这一行没有 `NeedFullReload`。** 类三的"太大"是**选型选错了**, 不是运行时降级 ——
运行时再怎么降级也救不了一个每秒整份推 1KB 的桶。

## 6. 测试: 这一类必须有的场景

* **旧数据贴新号**: 构造两个并发的重算, 断言客户端最后落地的是"某个真实存在过的版本",
  而且是号最大的那一份。
* **跳号是正常的**: 断言客户端**不**因为 `Seq` 不连续而重新进房。
* **"变成空"**: 让集合从有内容变成空, 断言界面真的清掉了(第 2 节那条)。
* **进房窗口的 A 段 / B 段**各压一遍, **这一桶单独压一次**(手册 §8.1)。
* 每加一个场景**做一次变异验证**。
