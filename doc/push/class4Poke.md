# 类四 戳一下: 帧里没有内容, 只有一句"你去拉"

> 四类共用的部分在 [`../pushDesignAndReview.md`](../pushDesignAndReview.md);
> 协议信封在 [`protocol.md`](protocol.md); 选型在 [`index.md`](index.md)。

**一句话**: 帧里根本没有状态, 只有一句"你去做件事"。客户端收到之后自己发一个普通请求拉全量。

**没有 id。** 这是它和前三类的根本区别 —— 前三类都在回答"这一帧接在哪", 类四不回答,
因为它不带内容。

**翻车形状是被按 id 丢掉。** 这一类的规矩是**反着的**: 别的帧判不出位置就该扔,
这一类**判不出位置也必须执行**。

## 1. 什么时候选它

两条路进来:

1. **选型三问都答"不是"** —— 说不清怎么描述这次变更, 或者描述比全量还贵。
   典型是分页查询结果(下一页是什么取决于客户端翻到哪了, 服务端说不出来)。
2. **2b 的首选出路** —— 一桶数据"变得很勤 + 只关心最新值 + 差一两秒没人在乎",
   它进类三会霸占每帧的信封, 退到这里之后:
   **成本随"真的在看的人"走** —— 没人打开那个面板就一次查询都不发生,
   而且**客户端的合并间隔就是延时旋钮**。

**它的代价是明码标价的一个额外 RTT。** 前三类都是 0。
拿这一个 RTT 换掉的是"发明一套 id + 一堆缺口判断", 很多时候划算。

## 2. 帧字段

    只有 RoomKey (deny 多一个 Reason)。几十到两百字节。

**别给它加 `Seq`。** 计数从 0 起算 + 编码器跳过零值, 就是为了让这类帧不白背一个恒为 0 的号
([协议篇](protocol.md)第 1 节)。

**同一类处理的还有两样东西**, 虽然它们不是"一桶数据":

* `deny{Reason}` —— 服务端拒绝这条连接, **终态信号**, `Reason` 必须让用户看得见。
  > 静默冻结 = 用户永远不知道自己在看旧数据。
* `NeedFullReload` —— 进房应答上那个布尔字段。它**不是一帧**, 但客户端处理它时按类四的规矩来
  (见第 4 节)。

## 3. 服务端

没有什么要算的 —— 这正是这一类的全部好处: **服务端不需要知道客户端有什么。**

要注意的只有一件事: 戳的**上游 fire 点**和别的桶共用同一批调用点。
漏戳的地方别的模式也会漏, 不存在只有一边对的情况。

## 4. 客户端: 怎么应用

**绝不许按 id / 按新旧丢弃。**

> 违反后果: 快照会过期, "你去重拉"不会 —— 它什么时候执行都是对的。按 Id 丢掉它只是白白多绕一轮。
>
> 历史上这条的理由更硬, 记在这里免得有人"顺手把 Id 判断加回来":
> `NeedFullReload` 曾经是**单独一帧**, 偏偏总在队列积压时才发出, 到达时客户端多半已经超时重发过,
> 配对 Id 必然对不上, 按 Id 丢就是**活锁**。那个形状已经删了, **但结论不变** ——
> 它现在的理由是纯粹的类四理由。

**自己合并连续的戳**(整页重拉设一个最小间隔, 如 5s), 否则一次爆发就是 N 次全量拉取。

> **限速期间要排队, 不许丢弃。**
> 违反后果: 丢了就再没人来对齐了 —— 连接是健康的、各桶的号也是连续的,
> **两条回退路径一条都不会触发**。

**"我正在拉"这个状态要登记**(手册 §5.5): 拉取在飞的期间收到的推送和应答要丢掉,
而**把它踢回去的是拉取请求自己的超时** —— 不是房间级超时, 也不是连接级超时。

> 真踩过: 那几个 POST 原来没传超时 —— 连接健康、进房超时也不会响(每次都收到了应答, 只是被丢掉),
> 房间就永远停在旧数据上。
> **修法: 凡是在"重拉计数 ++ 和 --"之间 await 的请求, 一律带超时。**

## 5. 这一类的降级路径

它**本身就是别人的降级终点**, 所以自己没有降级路径:

| 触发 | 动作 | 再来一次哪里不一样 | 有效? |
| --- | --- | --- | --- |
| 丢了一帧(**只可能发生在断线之后**) | **不用管** | 停在旧数据等下次戳; 重连会重进房, 也自愈 | ✅ |
| 戳得太密 | 客户端**合并**, 排队不丢弃 | 合并之后一次拉取覆盖多次戳 | ✅ |

**为什么 http 是最终兜底**: http 响应体**没有体积上限**(流式下发, 只有请求头有上限);
长连接上那些上限全是你自己设的。所以"退回 http 拉一次"下面没有别的路了 ——
这也正是[类三太大时退到这里](class3FullPush.md#5-这一类的降级路径)、
以及 `NeedFullReload` 值得存在的全部理由。

## 6. 测试: 这一类必须有的场景

* **配对 Id 对不上的那一帧必须被执行** —— 这是第 4 节那条规矩的钉子,
  写成"客户端超时重发过一轮之后再让服务端发出那一帧"。
* **戳一串**: 连续戳 N 次, 断言实际全量拉取次数被合并到远小于 N, **且最后一次一定发生**
  (限速期间排队不丢弃)。
* **拉取请求超时**: 让那个 http 请求永远不返回, 断言房间不会永久冻死。
* 每加一个场景**做一次变异验证**。
